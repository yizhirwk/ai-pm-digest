- **A Milan court put Revolut's Italian branch under judicial administration for one year over AML failures (Nov 16).** Prosecutors argued the branch's anti-money-laundering controls were weak enough to help clients tied to criminal cases, including mafia-linked ones, hide about €76.5M. The court appointed two administrators, who must report on AML controls within 90 days under a 15-point remediation plan. For a neobank with roughly 5M Italian customers, it shows how fast onboarding and weak transaction monitoring can turn into a regulator stepping in to run part of the business. - **Germany's competition authority told PayPal that its ban on merchant surcharges may break competition law (Nov 11).** The Bundeskartellamt's view is preliminary. It argues that stopping merchants from adding a fee when customers pay with PayPal keeps cheaper payment methods from competing, and that all shoppers end up paying for the cost through higher prices. Possible remedies include ordering PayPal to drop the ban and making it give up profits earned from the practice. PayPal disagrees but says it will engage with the authority. If the ban goes, European checkout teams may need to build PayPal-specific fees into their pricing and checkout logic. ([Electronic Payments International](https://www.electronicpaymentsinternational.com/news/germany-raises-competition-concerns-over-paypal-surcharging-ban/), [GRC Report](https://www.grcreport.com/post/germany-warns-paypal-its-payment-restrictions-may-violate-competition-law))
- **The CFTC sued Louisiana to protect prediction markets after a state court ordered 31 firms to stop offering event contracts (Nov 13).** The state order named Kalshi, Polymarket, Coinbase and Robinhood, among others. The CFTC argues that event contracts are swaps under the Commodity Exchange Act, so state gambling laws don't apply to them. This is the CFTC's 12th lawsuit against a state over event contracts, and a state-court injunction hearing is set for Nov 30. Until courts settle whether federal or state rules apply, any fintech offering event contracts has to be ready to switch them off state by state. ([CFTC press release](https://www.cftc.gov/PressRoom/PressReleases/9326-26), [The Block](https://theblock.co/news/regulation/2026-11-14-louisiana-ag-calls-cftc-chair-an-obsequious-standard-bearer-for-prediction-markets-following-agency-lawsuit-440342))

## PM Concept of the Day: The Cynefin Framework

Cynefin (pronounced "kuh-NEV-in") is a sense-making framework by Dave Snowden. It sorts situations into five domains, and each one calls for a different way of acting:

| Domain | What it means | How to act |
|---|---|---|
| **Clear** | Cause and effect are obvious | Sense → categorize → respond (best practice) |
| **Complicated** | Cause and effect can be worked out by experts | Sense → analyze → respond (good practice) |
| **Complex** | Cause and effect only make sense in hindsight | Probe → sense → respond (run safe-to-fail experiments) |
| **Chaotic** | No clear cause and effect | Act → sense → respond (stabilize first) |
| **Confused** (formerly "Disorder") | You don't yet know which domain you're in | Work that out first |

On PMP and Agile exams, Cynefin is often the reasoning behind **choosing a delivery approach**: predictive planning suits Clear and Complicated work, and iterative or adaptive approaches suit Complex work.

Fintech example: a bank's PSD2 API migration is mostly **Complicated**. Experts can specify it up front, so a detailed plan works. Launching a new agent-driven payments product is **Complex**: no one knows how customers or fraudsters will behave, so you run small pilots behind feature flags. A live card-processing outage is **Chaotic**: the incident commander restores service first, and root-cause analysis waits until afterward. A good PM recognizes which domain a workstream is in before choosing between a Gantt chart and a set of experiments.

## One Thing to Try Today (10 minutes)

Pick a project you're on, or a fintech product you know well, such as a card launch or a KYC rebuild. List its 4–6 main workstreams. Label each one with a Cynefin domain and write one line on why. Then check whether each workstream is managed the way its domain needs: a fixed plan for a Complex item, or open-ended experiments for a Clear one, are both mismatches. Being able to explain *why* part of a project needs a different approach is how a PM makes a convincing case for a hybrid approach to stakeholders.
