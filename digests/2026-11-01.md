## PM Concept of the Day: Configuration Management

Configuration management is the discipline of identifying, version-controlling, and tracking the state of every deliverable and component (code, infrastructure settings, documents, requirements) so that you always know exactly what is in each release and can reproduce or roll back any baseline. In PMBOK it works hand in hand with change control: change control decides *whether* a change is approved, while configuration management records *what* actually changed, verifies the result matches the approved baseline (configuration verification and audit), and keeps the status accounting current. In fintech, this is what lets a PM answer an auditor's question, "which version of the sanctions-screening rules was live on March 3?", with evidence instead of memory. The deadlines above are a good example: if a team must pull a non-compliant stablecoin product by Jan 8, config management tells them which services, feature flags, and contracts reference it. For the exam, remember the four activities: identification, status accounting, verification, and audit.

## One Thing to Try Today (10 minutes)

Pick one system you use or know (a payments app, a work tool, even a personal project) and sketch a mini "configuration item list": five items that would need version control for a release (e.g. API schema, fee table, compliance rules, deployment config, release notes). For each, write where its version lives and who approves changes. Note any item where you can't answer, since that gap is your first configuration-management risk.
